Trial and results
- 32 measured V2 fixtures: 4 page counts × 4 document sizes × 2 edit families.
- Eight separate one-page legacy compatibility fixtures cover `format_version` 1 and 2 with `schema_version` 1, each at 16,384, 131,072, 524,288, and 1,048,575 bytes. All parse/serialize byte round trips passed; the V2 patch candidate is not run against V1.
- Five alternating warm-up pairs and 100 deterministically shuffled measured pairs per V2 fixture; exactly 50 snapshot-first and 50 patch-first pairs each.
- 6,400 measured candidate executions total (3,200 per candidate); zero errors.
- Every typed patch expanded to byte-identical canonical output and the same SHA-256 as its snapshot counterpart.
- Nine explicit negative checks rejected: unknown version, duplicate page ID, duplicate block ID, colliding slug, missing navigation target, cyclic page graph, malformed JSON, excessive nesting depth, and incorrect patch base digest.
- Modeled client round trips per save: 3 for both candidates (mint command, binary stage upload, final save command); provider operations remain model inputs rather than observed traffic.
- Median fixture upload-byte reduction: 98.38896% for sparse edits and 39.93208% for broad edits that change 60% of text blocks. Each family weights all 16 size/page-count fixtures equally.
- Pooled p95 local transform ratios, typed patch / snapshot: 1.7545 at 16,384 bytes; 1.8407 at 131,072; 1.6091 at 524,288; 1.9287 at 1,048,575.
- Five of 32 individual V2 fixture p95 ratios exceeded 2x; the maximum was 2.62765x for the 1-page, 524,288-byte sparse fixture. Thus the typed-patch candidate fails the per-fixture latency gate despite passing pooled-by-size p95, correctness, and byte-savings gates.
- Legacy V1-shaped fixture sizes through 1,048,575 bytes and V2 document/upload boundaries at 1,048,575 and 1,048,576 bytes passed; 1,048,577-byte V2 boundaries and over-cap legacy target were rejected.
- Legacy shape and JSON round-trip checks are harness-level only; this benchmark does not invoke the Rust V1 decoder.
- These are local Node fixture results, not a production-equivalent Worker/D1/R2 comparison. D22 selects full-snapshot transfer for initial V2 runtime; no patch payload is accepted. Every saved revision remains a full canonical snapshot. A future patch decision requires runtime-equivalent correctness, per-fixture latency, memory, and provider-operation evidence.

Follow-up exact-head restore-safe allocator correction
- Codex's review thread on `6723bba612d37ff2324e242e8d43a9ecfac051a0` identified that a late writer could be stranded if D1 restore rolled back the only namespace/high-water registry. Official Cloudflare D1 docs say Time Travel overwrites all D1 data in place. R2's current consistency docs say conditional writes are evaluated atomically and R2 reads/writes/lists are strongly consistent globally.
- D22 now puts the authoritative monotonic attempt sequence in `private/stage-control/sequence-v1`, outside restorable D1 state. The Worker reserves the D1 attempt row, advances the R2 counter with an ETag-conditional write, persists the assigned sequence/key in D1, and only then starts the stage-object PUT. Failed allocations leave safe gaps and fail closed; the counter is never reset to zero. Stage keys use the fixed-width sequence and unique attempt ID under `private/stage/`.
- The lifecycle regression starts a pass through sequence 6, restores D1 (resetting the saved cursor but keeping the simulated R2 counter), materializes an old sequence-2 writer after restore, then admits sequences 7–9 outside the current pass. The next pass revisits the late object, enforces the 24-hour age gate, and deletes all eligible objects. This proves the deterministic model only.
