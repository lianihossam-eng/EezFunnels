# D16 - Closed settings inspector and versioned theme overrides

Status: accepted for PR-011.

PR-011 extends the PR-010 visual editor with a server-owned `settings_schema` for the five planned control kinds: text, color, select, toggle, and image. The schema is generated from the existing closed `SectionContent` variants and the closed `ThemePreset` catalog. It describes only existing section fields, their bounded repeated-item indices, the selected preset, the primary color, and the button-corner toggle. It does not expose generic paths, arbitrary content, CSS, HTML, manifests, or client-authored schemas.

The browser submits sparse typed changes against stable schema field IDs. Commands rebuild the schema for the owned immutable base revision, require each ID and control kind to match that schema, reject duplicate or unknown changes and unknown nested fields, validate values and the final rendered document, then preview or save the result. Each text value is capped at 4 KiB, each envelope at 128 changes, and compact serialized changes at 12 KiB. The 12 KiB aggregate budget leaves room for route, revision, section-order, and envelope data within PR-010's frozen 16 KiB API request cap; the command layer also preserves its 17 KiB cap after the server adds the route-owned funnel ID. The existing order-only request remains valid and means “preserve all settings.” Preview remains read-only. Save still creates a new immutable revision through the current idempotency receipt and editor-head compare-and-swap path. C-01, C-03, C-04 and their frozen contract files remain unchanged.

Text and image changes map only to the corresponding existing typed `SectionContent` fields. The optional testimonial attribution is explicitly nullable so clearing its text restores `None`; empty strings remain text for non-nullable controls. Select chooses one of the five existing theme presets. Color may override only `color-primary` and must be a six-digit hex color; an inherited color is represented as a null override plus the server-computed effective color. Toggle controls only whether `radius-button` is zero; false restores the selected preset's value. `ThemeTokens::new` remains the final CSS-token validator and digest owner. Lists remain fixed-length in this PR; indexed controls edit existing Features, Testimonials, and Footer items without adding, removing, or reordering them.

Historical `FunnelSnapshotV1` remains strict and byte-compatible. The decoder dispatches on `format_version`, validates V1 exactly as before, and also accepts a strict private `FunnelSnapshotV2` with the same `schema_version: 1`, blueprint, preset, sections, and typed contents plus closed `theme_overrides` fields for the primary color and button corners. V1 decodes with no overrides. Order-only saves preserve the source snapshot format, including V1. A settings save that needs a non-default color or square-button override writes V2; V2 settings and order-only saves preserve the override. Existing rows are immutable and never rewritten. This is snapshot-format evolution under D13, not a schema-version change or database migration.

The preview keeps D15's empty iframe sandbox, network-denying CSP, escaped text, and inert link behavior. Preview responses also return the validated settings projection so changing presets updates the displayed inherited color without turning it into a custom override. Since remote images remain blocked, an image edit appears as an escaped inert placeholder containing its alternative text; published rendering continues to use the validated image URL. Placeholder CSS is preview-only, so the published renderer-v2 stylesheet and output bytes remain unchanged. No image fetch, upload, proxy, or network permission is added.

This decision supersedes D15's PR-010 restriction against settings in preview and save and makes one narrow exception to its receipt precedence: the HTTP adapter rejects duplicate object keys anywhere in the bounded JSON body as `validation/invalid_json` before receipt lookup, including when the idempotency key already has a receipt. This prevents JSON normalization from collapsing ambiguous values. For syntactically valid JSON, D15's receipt classification and replay ordering remain unchanged. D15's order validation, immutable revision ownership, editor-head CAS, stale-save behavior, renderer ownership, and preview isolation remain in force. No frozen contract or SQL migration changes are permitted for this feature.

Verification covers all five controls, malformed and unknown fields, exact and exceeded aggregate request budgets, V1 duplicate-key rejection and read/order-save compatibility, V1 settings-save to V2, strict V2 round trips, nullable attribution clearing, immutable save/replay/CAS behavior, definitive 4xx recovery, and hydrated browser edits and reloads. There is no database migration: the compatibility step is the versioned snapshot decoder/encoder and its V1-to-V2 tests.
